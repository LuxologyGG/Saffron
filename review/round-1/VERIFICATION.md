## Regression sweeps

- **Console errors/warnings:** zero across all 6 pages × 2 viewports (1440×900, 390×844) = 12 combinations. No `console.error`, `console.warning`, or uncaught page errors on any combination (networkidle + 1.5s settle).
- **External runtime requests:** zero. Every request across all 12 page/viewport loads resolved to `localhost:8145` or `data:`/`about:` — no third-party host contacted.
- **Nav markup byte-identical across pages:** **FAILS — new regression, see VER-2 below.** index.html and menu.html now prerender `.nav__call`'s `href`/text; catering.html, about.html, contact.html, and 404.html still ship the old unbound placeholder. This is new since Phase 3 (PROGRESS.md documents "nav and footer byte-identical across pages" as a verified invariant at initial build).
- **Footer markup byte-identical across pages:** trivially true right now (all six are identically *empty* in static HTML — see item 7/VER-1), which is the underlying defect, not a pass.
- **Menu integrity (14/12/8/3/7/6 = 50):** confirmed both `java_script_enabled=True` and `False`, per-section counts identical in both modes, no double-render (single `innerHTML` assignment confirmed in `renderMenu()`).
- **No em dash in shipped html/css/js:** confirmed zero (`grep -rlP "\x{2014}"` across all `*.html`/`*.css`/`*.js`, excluding `research/`/`review/`/`tools/`). The em-dash-like glyph visible in review-card attributions is a CSS `::before` decorative line (`content:""; width:14px; height:1px`), not a Unicode character.
- **Reduced motion renders finished pages:** confirmed by screenshot on index.html (top, mobile hero), about.html (dusk hero shows the night-state photo at opacity 0.5 immediately, ornament thread fully drawn not clipped), menu.html (filmstrip and hero fully visible, no stuck loader). No page observed stuck at a loading/transitional state under `reduced_motion: reduce`.

## New findings filed (see REVIEW-LOG.md addendum for full detail)

- **VER-1 (CRITICAL):** `[data-site-footer]` renders completely empty with JS disabled on all six pages — fails CP-1's explicit Verify step. Root cause: the footer shell has no static or `<noscript>` fallback anywhere; it exists solely as `app.js renderFooter()` output. Causes item 7 (CP-1) to be reverted to **still-open** despite genuine partial progress on menu.html/index.html/contact.html.
- **VER-2 (CRITICAL):** The round-1 fix pass broke the previously-verified "nav byte-identical across pages" invariant. index.html/menu.html's `.nav__call` now diverges from catering.html/about.html/contact.html/404.html's — the Call button is non-functional with JS off on 4 of 6 pages, and the shared nav partial is no longer literally identical sitewide.
