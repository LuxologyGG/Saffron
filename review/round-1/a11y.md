# Accessibility Review, Round 1

**Site:** Saffron and Rice (Torrance, CA) — 6 pages, zero-build static site
**Lens:** Accessibility (AX)
**Reviewer port:** 8134
**Date:** 2026-07-17

## Score: 6.8 / 10

Strong foundations: skip links move real focus on every page, focus-visible rings are
present and high-contrast everywhere, tap targets are correct except one systemic footer
issue, alt text is meaningful throughout, JSON-LD/sitemap/robots/404-noindex are all
correct, heading outlines are clean with no skips, and reduced-motion renders finish
completely on every page with zero frozen mid-reveal states. Two real measured contrast
failures in the `.on-teal` color scope and a confirmed focus-trap failure in the mobile
menu overlay keep this out of gate-ready territory. This is an honest round-1 baseline,
not a rubber stamp.

## Checks run (with evidence)

1. **Contrast, computed-style pass over all 6 pages** — Playwright script (`ax_contrast.py`) walked every leaf text node on index/menu/catering/about/contact/404 at 1440×1000, composited `background-color` up the ancestor chain, computed WCAG contrast ratios against the actual font-size/weight large-text threshold. Flagged 4-5 apparent failures per page; cross-checked each by hand.
2. **Contrast, pixel-sampled follow-up** — Because the initial pass doesn't account for background *images*, re-verified the nav-over-hero flags (`nav__word`, `.swap` phone) by cropping real screenshots and sampling actual rendered pixels (`ax_pixel_contrast.py`): all were false positives caused by the hero's ink scrim (17.24:1, 10.51:1, 17.32:1 measured — confirmed CSS `.cat-hero__bg::after` / equivalent scrims are present and effective).
3. **Contrast, token math + live computed-style extraction for `.on-teal`** — Computed every `.on-teal` semantic token (`--fg-soft`, `--fg-faint`, `--price`) against both `--bg` (teal-deep) and `--bg-2` (teal) by hand from the exact `color-mix()` formulas in `tokens.css`, then confirmed the two failures (AX2, AX3) against live `getComputedStyle` pixel values pulled from the running page at the actual breakpoint/scroll state where each occurs (menu.html scrolled into the pinned hero at 1440×900; index.html `#catering` section). Also confirmed passes: `.on-teal` `--fg-soft` 7.29:1, `.call-panel__phone` (large text) 4.04:1 > 3:1 large-text threshold, `accent-lite` on teal-deep 7.09:1.
4. **Contrast, light/dark scope sanity sweep** — Verified `--fg-soft`/`--fg-faint`/`--price`/focus-ring tokens against `--paper` (light) and `--ink` (`.on-dark`) grounds all pass comfortably (5.26:1 to 17.24:1 range); button-070 hover fills (`accent-ink` on `accent-base` 5.90:1; `paper` on `ink` 17.24:1) pass.
5. **Focus-visible probe** — Tabbed 25 stops through index.html at 1440×900, recorded `outline-style/width/color/offset` via `getComputedStyle` for every stop (skip-link, nav links, buttons, footer links): 100% show a solid 2px ring with 3px offset, in either `accent-deep` (paper scope, 5.82:1 against paper) or `accent-lite` (dark scope, 9.70:1 against ink). No `outline: none` found anywhere in the CSS (`grep`).
6. **Skip link, all 6 pages** — Automated probe (`ax_focus_skip.py`): first Tab lands on `.skip-link` with a visible ring on every page; pressing Enter moves real `document.activeElement` to `<main id="main">` on every page (confirmed by tag/id in the returned object, not just visual position).
7. **Mobile menu: aria-expanded, inert, focus order, Escape** — Automated probe (`ax_mobile_menu.py`) at 390×844 on index.html: `aria-expanded` correctly flips `false→true→false`; `#main` and `[data-site-footer]` correctly get `inert` while open and lose it on close; full 15-stop Tab sequence recorded and inspected (surfaced AX1); Escape correctly closes the overlay, flips `aria-expanded` back to `false`, and returns focus to `.nav__toggle` (`document.activeElement` confirmed by tag/class, not assumed).
8. **Tap targets at 390px** — Measured every `a`/`button` bounding box via `getBoundingClientRect()` on all 6 pages (`ax_tap_targets.py`); full JSON dump saved; 2 systemic footer-link width fails found (AX5), everything else (22, 15, 19, 18, 22, 16 interactive elements per page respectively) passes ≥44×44.
9. **tel: link correctness** — Grepped `data.js` and all HTML for `tel:`; confirmed single source of truth `phoneHref: "tel:+13105040310"` matches the printed `(310) 504-0310` number, bound consistently via `data-bind-href`.
10. **Keyboard end-to-end, no stuck loops** — Full automated Tab traversal of menu.html (longest page, 32 interactive elements) for 42 iterations (`ax_full_tab_menu.py`): no stuck-loop detected, sticky mono index links (`01 Appetizers` … `06 Party Platters`) all reachable, no focus loss into `document.body`. Loader focus check on a genuinely fresh (unseeded) session (`ax_loader_focus.py`): loader renders on first visit, removes itself after ~3.5s, and the very next Tab correctly lands on `.skip-link` with no stranded focus.
11. **Reduced motion, all 6 pages, full-page screenshots read visually** — Emulated `prefers-reduced-motion: reduce`, loaded and screenshotted (both above-the-fold and full-page) index/menu/catering/about/contact/404 (`ax_reduced_motion.py`). Read every screenshot: all text fully legible, all reveal groups settled, no mid-blur/mid-translate frozen elements, odometer counts show final values (not `0`) confirmed both in code comment ("Rest state is the final number") and in the index.html catering section screenshot.
12. **Alt text audit** — Grepped every `<img>` across all 6 HTML files and every JS template that injects `<img>` (`home.js`, `page-menu.js`, `page-about.js`, `page-catering.js`, `page-contact.js`, `page-404.js`, `app.js`). All content photography (hero, menu section bands, about photos, contact interior/maps) carries a real, specific, descriptive `alt`. All purely decorative images (`nav__seal` emblem, loader emblem, hero background images sitting inside `aria-hidden="true"` wrappers) correctly use `alt=""`. The loader additionally carries `role="status" aria-label="Loading"` on its container so the empty-alt emblem inside it is not a dead end for AT users.
13. **JSON-LD validity, all 5 indexable pages** — Parsed the `application/ld+json` block on index/menu/catering/about/contact with Python's `json.loads`. All 5 valid, all `@type: "Restaurant"`, all identical and correct NAP (name, `telephone: "+13105040310"`, full `PostalAddress`), all `openingHoursSpecification` with `dayOfWeek` Monday-Sunday, `opens: "11:00"`, `closes: "20:00"` (matches the Mo-Su 11:00-20:00 requirement).
14. **sitemap.xml / robots.txt / 404 noindex** — Read all three directly. `sitemap.xml` lists exactly the 5 indexable pages (`/`, `menu.html`, `catering.html`, `about.html`, `contact.html`), no 404 entry. `robots.txt` has `User-agent: * / Allow: /` plus a `Sitemap:` line. `404.html` carries `<meta name="robots" content="noindex, nofollow">`.
15. **Heading structure / document outline, all 6 pages** — Extracted every `h1`-`h6` in DOM order per page (`ax_headings.py`) and checked for level skips programmatically plus manual read. Exactly one `h1` per page on all 6; zero level skips anywhere (catering.html and about.html's `h3.h4` step/value-prop headings correctly follow their parent `h2`, not skip to `h4`). catering.html's FAQ correctly uses `<dl><dt><dd>` semantics rather than a heading level, which is appropriate and not a skip.
16. **`lang`/`dir` attributes** — Confirmed `<html lang="en">` on all 6 pages. Grepped all 14 `.script-fa` occurrences across every HTML file and every JS template; 12/14 correctly carry `lang="fa" dir="rtl"`; 2 decorative aria-hidden ghost-word instances do not (AX4).
17. **Landmark/aria-label sanity** — Confirmed the two `<nav>` elements per page (`header.nav` primary nav vs. the mobile overlay's `<nav>`) carry distinct `aria-label`s ("Primary" vs. "Site menu"), no landmark ambiguity. Confirmed `aria-current="page"` is set (not just a color class) on the active nav link via `markActive()`. Confirmed review star ratings pair an `aria-hidden` SVG row with a `.sr-only` "N out of 5 stars on {platform}" text alternative in every one of the 3 places reviews render (home.js, page-about.js, page-catering.js). Confirmed the map-toggle button on contact.html uses the correct `aria-pressed` toggle-button pattern, not a misapplied `aria-expanded`.
18. **Page `<title>` uniqueness** — Read `<title>` from all 6 pages; all unique and descriptive.

## Notes

- The `.on-teal` alternate dark stage (teal bowl-ornament ground) is clearly newer/less
  battle-tested than the primary `.on-dark` (ink) stage: every `.on-dark` contrast pair I
  checked passes comfortably, while `.on-teal` produced both real failures in this review
  (AX2, AX3). Worth a full manual pass over every `.on-teal` usage (currently: catering.html
  halal section, contact.html call-panel, index.html catering-count section, menu.html
  pinned carta panel) rather than patching just the two instances caught here, in case the
  same `--price`/`--fg-faint` combination recurs elsewhere at a differently-scaled font size.
- AX1 (focus trap) is the most consequential finding for a screen-reader or keyboard-only
  visitor: it's the difference between "the menu behaves like a real modal" and "the menu
  is a panel that happens to cover most of the screen." Recommend fixing before this gates.
- Everything explicitly required by the brief's accessibility floor (skip link real-focus,
  reduced-motion finished renders, no-JS nav fallback via `html:not(.js) .nav__links`,
  meaningful alt text, sr-only star-rating text, inert-on-open for `#main`/footer) is present
  and working; the gaps found are narrower and more surgical than a first-pass audit often
  turns up, which is why this lands at 6.8 rather than lower — but 6.8 is still short of
  gate-ready given two measured AA contrast fails and a real focus-containment bug.
